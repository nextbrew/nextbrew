# 互換性

formula のコマンド、cask のすべての artifact とコンテナ、bundle、services は、変更のたびに統合テストが macOS と Linux で実際に動かして確かめています。`nb migrate` も CI で実際の Homebrew を nextbrew に移して確かめています。
テストは Apple Silicon の macOS、x86_64 と arm64 の Linux で動かし、Debian・Fedora・Arch・openSUSE のコンテナでも手動で動かしています。Intel macOS はサポートしていません。Homebrew が bottle を配布しておらず、`darwin-x64` のビルドもテストしていません。

## Homebrew と同じように動くもの

| 領域 | 内容 |
| --- | --- |
| formula | install、uninstall、upgrade、outdated、list、info、link、unlink、pin、autoremove、deps、uses、search |
| cask | app、suite、binary、pkg、installer。dmg、zip、tar。フック（`*_steps`）。upgrade（`--greedy`、`--greedy-latest`、`--greedy-auto-updates`）。uninstall と `--zap`。`--language` |
| Bundle | Brewfile。`flatpak`、`winget` と各拡張を含む |
| Services | macOS は launchd、Linux は systemd |
| Tap | `nb tap` |
| その他のコマンド | cleanup、fetch、leaves、desc、home、source、shellenv、config、`--prefix` / `--cellar` / `--cache`、vulns、version-install、man |
| 移行 | `nb migrate`。formula、cask、tap、pin、service |
| ソースからのビルド | C、Rust、Go。試した主要 formula 25 個すべてが Linux と Apple Silicon の macOS でビルドできる |

## nextbrew が違うところ

- サードパーティの tap は `nb trust` で信頼してから読み込まれます。
- service のラベルは `dev.nextbrew.<formula>` です。
- cask のフックに未知のステップがあるか、ステップが失敗すると、インストールはロールバックされます。
- Brewfile では、`build-from-source` 以外のビルド `args`（`HEAD` など）は理由つきで失敗します。
- 開発者向けコマンド（create、audit、bottle）は予定していません。

コマンド名、オプション、終了コードは Homebrew に従います。nextbrew が Ruby を実行するのはソースからのビルドのときだけです。
理解できないステップは、黙ってスキップせず報告します。
