# nb services

```sh
nb services [OPTIONS] [COMMAND]
```

`nb services` is `brew services` for nextbrew. On macOS it uses launchd and
on Linux systemd, with labels of the form `dev.nextbrew.<formula>`.

## Subcommands

| Subcommand | Meaning |
| --- | --- |
| `list` (alias `ls`) | List all managed services for the current user (or root) |
| `info` (alias `i`) | Show a service's status |
| `run` | Run a service without registering it to launch at login (or boot) |
| `start` (aliases `launch`, `load`, `s`, `l`) | Start a service now and register it to launch at login (or boot) |
| `stop` (aliases `unload`, `terminate`, `term`, `t`, `u`) | Stop a service and unregister it from launching at login (or boot) |
| `kill` (alias `k`) | Stop a service now but keep it registered |
| `restart` (aliases `relaunch`, `reload`, `r`) | Stop (if necessary) and start a service again |
| `cleanup` (aliases `clean`, `cl`, `rm`) | Remove all unused services |

## Options

| Flag | Meaning |
| --- | --- |
| `--sudo-service-user <SUDO_SERVICE_USER>` | When run as root on macOS, run the service(s) as this user |
| `--auto-init` | Initialize without prompting |
| `-v`, `--verbose` | Increase output verbosity |
| `-q`, `--quiet` | Suppress output, only show errors |

## Examples

```sh
nb services list
nb services start postgresql@16
nb services restart postgresql@16
```

## Differences from brew

Services work like Homebrew's on macOS (launchd) and on Linux (systemd user units, or
system units under `sudo`).
Set `NEXTBREW_SERVICES_NO_DOMAIN_WARNING=1` to hide the launchd domain warning.
