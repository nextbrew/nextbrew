# Compatibility

Formula commands, every cask artifact and container, bundle and services are
exercised end to end on macOS and Linux by the integration tests on every change,
and `nb migrate` moves a real Homebrew installation into nextbrew in CI.
They run on Apple Silicon and Intel macOS, x86_64 and arm64 Linux, and (run by hand) in Debian,
Fedora, Arch and openSUSE containers. Homebrew ships no bottles for Intel macOS,
so there nextbrew, like Homebrew, builds every formula from source.

## Works like Homebrew

| Area | What |
| --- | --- |
| Formulae | install, uninstall, upgrade, outdated, list, info, link, unlink, pin, autoremove, deps, uses, search |
| Casks | app, suite, binary, pkg, installer; dmg, zip, tar; hooks (`*_steps`); upgrade, with `--greedy`, `--greedy-latest` and `--greedy-auto-updates`; uninstall and `--zap`; `--language` |
| Bundle | Brewfiles, including `flatpak`, `winget` and the extensions |
| Services | launchd on macOS, systemd on Linux |
| Taps | `nb tap` |
| Migration | `nb migrate`: formulae, casks, taps, pins and services |
| Building from source | C, Rust and Go; all 25 popular formulae tried build on Linux and Apple Silicon macOS |

## Where nextbrew differs

- A third-party tap loads only after `nb trust`.
- Service labels are `dev.nextbrew.<formula>`.
- A cask hook step nextbrew does not know, or one that fails, rolls the install back.
- In a Brewfile, build `args` other than `build-from-source` (such as `HEAD`) fail with the reason.
- Developer commands (create, audit, bottle) are not planned.

Command names, options and exit codes follow Homebrew. nextbrew runs Ruby only
to build from source. A step it does not understand is reported, not skipped silently.
